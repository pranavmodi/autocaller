# Decisions — 2026-06-20

## D-2026-06-20-01 — Activate the AI Audit email variant as the first-touch; drop the review-evidence gate
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** Set `LEAD_GEN_FIRST_TOUCH_VARIANT=ai-audit` and
  `REQUIRE_REVIEW_EVIDENCE_FIRST_TOUCH=false` in `.env`. New first-touch lead-gen
  emails now compose with the forced-only `ai-audit` composer variant (offers the
  AI-readiness audit as the primary CTA, with a contact-attributed tracked link),
  instead of the `review-evidence` variant. The review-evidence gate is turned off
  because the audit angle does not depend on a citable Yelp quote; that gate runs
  before variant selection and is not variant-aware, so leaving it on would hold
  audit emails for any firm without usable review evidence. Follow-ups are
  unaffected (never gated, keep their sequence variant).
- **Why:** Day-one funnel showed 7 firms clicking the signature audit link but 0
  completions; the audit is a stronger, lower-friction first-touch hook than an
  inferred review-evidence pivot, and routing first-touch through the audit
  variant raises entry intent (audit as primary CTA, not a footer link).
  `LEAD_GEN_AUTO_APPROVE_SEND=true` is on, so the next daily run will compose and
  auto-send audit first-touch emails at the 09:00–11:30 PT window — every send
  still passes the PHI egress guard, deliverability breaker, and suppression.
- **Refs:** app/services/lead_gen_email_agent.py (forced-variant + gate at ~292,
  ~345); app/skills/possible-minds-lead-email-composer/variants/ai-audit/;
  .env (LEAD_GEN_FIRST_TOUCH_VARIANT, REQUIRE_REVIEW_EVIDENCE_FIRST_TOUCH).
  Reversible: set the variant back to `review-evidence` and the gate back to
  `true`.
