# Decisions — 2026-06-22

## D-2026-06-22-01 — Per-run composer-variant override + follow-up variant knob
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** daily-run now accepts a composer_variant_key (REST + CLI --variant + UI 'Composer variant (this run)' picker) that pins one active variant on every email in the run, first-touch and follow-up. Added LEAD_GEN_FOLLOW_UP_VARIANT env (default empty) symmetric to LEAD_GEN_FIRST_TOUCH_VARIANT. Precedence: per-run/explicit key > env knob > auto A/B.
- **Why:** Operators needed to drive a whole run onto one variant (e.g. ai-audit) without per-email Redo-compose, and to use weight-0 forced-only variants on follow-ups (the A/B pool excludes weight-0, so follow-ups could never get ai-audit). Per-run override is the clean lever; LEAD_GEN_FOLLOW_UP_VARIANT mirrors the existing first-touch knob.
- **Refs:** app/services/lead_gen_daily.py, app/services/lead_gen_email_agent.py, app/api/lead_gen.py, app/cli.py, frontend/app/lead-gen/page.tsx

## Lead-gen email transport caps: Zoho first, then Resend

- **Decision:** lead-gen sends now use a provider-aware transport router. Default policy caps Zoho API at 20 sent emails per PT day and routes remaining daily-budget sends through Resend when configured.
- **Why:** Protect the active Zoho mailbox/API sender domain while increasing daily outreach capacity through the already configured Resend channel.
- **Refs:** app/services/lead_gen_transport.py, app/services/action_execution.py, app/services/lead_gen_cybernetic.py, app/services/lead_email_composer.py, frontend/app/lead-gen/page.tsx

## D-2026-06-22-02 — Route offline text LLM calls through OpenClaw proxy gateway (OAuth) instead of direct OpenAI API key
- **Area:** infra
- **Status:** accepted
- **Decision:** Route offline text LLM calls through OpenClaw proxy gateway (OAuth) instead of direct OpenAI API key
- **Why:** Consolidates the offline/batch text-classification calls (lead-extractor, name classifier, phone-sim reply) onto the gateway's ChatGPT OAuth (openclaw/proxy, gpt-5.4) via call_skill_json + new SKILL.md files, so no platform sk- key is needed for them. Audio (STT/TTS/Realtime calling) and the latency-critical live IVR navigator stay on OPENAI_API_KEY: OAuth can't serve audio endpoints and IVR can't take gateway latency. Model overrides LEAD_EXTRACTOR_MODEL / LEAD_NAME_CLASSIFIER_MODEL / PHONE_SIM_REPLY_MODEL all default openclaw/proxy. Smoke-tested live.
- **Refs:** app/services/lead_extractor.py, app/cli.py, app/llm.py, app/skills/{lead-extractor,lead-name-classifier,phone-sim-reply}/SKILL.md

## D-2026-06-22-03 — AI Visibility report pre-generation bridge for lead-gen
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** PossibleOS can now ensure an AI Search Visibility report through the `ai-visibility` CLI before composing an email. The bridge reuses an existing scanned report by firm/domain unless `--force` is passed, and caches a compact report package on `lead_gen_batch_items.reason_json.ai_visibility_report`.
- **Why:** The visibility-report email must use pre-generated, provenance-backed report facts and report URLs rather than asking the lead-email composer to invent numbers.
- **Refs:** app/services/ai_visibility_bridge.py, app/services/lead_email_composer.py, app/skills/possible-minds-lead-email-composer/variants/ai-visibility-report/SKILL.md, app/cli.py
