# Decisions — 2026-06-22

## D-2026-06-22-01 — Per-run composer-variant override + follow-up variant knob
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** daily-run now accepts a composer_variant_key (REST + CLI --variant + UI 'Composer variant (this run)' picker) that pins one active variant on every email in the run, first-touch and follow-up. Added LEAD_GEN_FOLLOW_UP_VARIANT env (default empty) symmetric to LEAD_GEN_FIRST_TOUCH_VARIANT. Precedence: per-run/explicit key > env knob > auto A/B.
- **Why:** Operators needed to drive a whole run onto one variant (e.g. ai-audit) without per-email Redo-compose, and to use weight-0 forced-only variants on follow-ups (the A/B pool excludes weight-0, so follow-ups could never get ai-audit). Per-run override is the clean lever; LEAD_GEN_FOLLOW_UP_VARIANT mirrors the existing first-touch knob.
- **Refs:** app/services/lead_gen_daily.py, app/services/lead_gen_email_agent.py, app/api/lead_gen.py, app/cli.py, frontend/app/lead-gen/page.tsx
