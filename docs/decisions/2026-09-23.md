# Decisions — 2026-09-23

## D-2026-09-23-01 — Bound Job Agent preparation and make stale polling visible
- **Area:** product
- **Status:** accepted
- **Decision:** Cap draft preparation at four minutes and each application-agent gateway call at 150 seconds. Persist granular research phases. If the browser cannot refresh an active application, replace the spinner with an explicit refresh failure and reload control while background polling continues. A preparation timeout stops before sending and remains safe to retry.
- **Why:** A Zayed Law preparation finished in the database after contact research, but gateway delay and database-pool exhaustion prevented the modal from receiving the terminal state, leaving a misleading indefinite spinner.
- **Refs:** app/services/job_agent_processing.py, app/services/job_agent_research.py, frontend/components/JobApplicationControls.tsx

## D-2026-09-23-02 — Use native OpenClaw RPC with separate interactive and batch lanes
- **Area:** infra
- **Status:** accepted
- **Decision:** Replace the shared structured-call client's OpenAI-compatible completions transport with native OpenClaw WebSocket RPC. Route Job Agent work to one serialized interactive lane and recurring research and maintenance to one serialized batch lane; allow those two lanes to run concurrently.
- **Why:** Agent IDs do not create independent OpenClaw queues, and the completions endpoint cannot select a lane. Explicit RPC lanes keep bulk research from blocking operator-triggered applications while retaining a conservative host-wide concurrency ceiling.
- **Refs:** app/services/llm_gateway.py, OPENCLAW_GATEWAY_RPC_URL, OPENCLAW_RPC_INTERACTIVE_LANE, OPENCLAW_RPC_BATCH_LANE

## D-2026-09-23-03 — Use raw model runs for supplied-evidence JSON work
- **Area:** infra
- **Status:** accepted
- **Decision:** Disable OpenClaw tools and workspace bootstrap for Job Agent drafting, classifiers, composers and other calls whose complete evidence is already in the request. Keep the minimal tool-enabled runtime for web-research calls.
- **Why:** Live lane testing showed that explicit lanes remove queue blocking, but tool-runtime startup and cleanup can still dominate latency. Supplied-evidence judgments do not need that machinery.
- **Refs:** app/services/llm_gateway.py, app/services/job_agent_processing.py, allow_tools

## D-2026-09-23-04 — Use Jev for semantic job-page identity verification
- **Area:** product
- **Status:** accepted
- **Decision:** Replace contiguous title and employer token matching with one TypeSafe Jev Noul that judges whether the selected page describes the same employer and job role as the saved listing. Persist its model, probability, threshold and usage with the application evidence. Keep URL trust, company-domain ownership and quoted-evidence validation deterministic.
- **Why:** Job boards append presentation labels such as `- Remote` that official role pages may state elsewhere. Exact string matching rejected Kake's real Forward Deployed Engineer page even though the employer, role and responsibilities matched. Semantic identity is the judgment; domain and evidence integrity remain mechanical safety checks.
- **Refs:** app/services/job_agent_research.py, JOB_AGENT_JOB_IDENTITY_MIN_PROBABILITY, TYPESAFE_API_KEY

## D-2026-09-23-05 — Reserve regex and string matching for guaranteed mechanical decisions
- **Area:** process
- **Status:** accepted
- **Decision:** Repository-wide, regexes and string heuristics may decide only mechanical cases whose representation and invariants guarantee correctness. Semantic identity, equivalence, classification, relevance and change detection use TypeSafe Jev for narrow typed judgments or a structured-output LLM for evidence synthesis and generation. Candidate prefilters may remain deterministic but cannot make the final semantic decision. Persist model evidence and uncertainty and route ambiguous results to review.
- **Why:** Heuristic string rules accumulate brittle exceptions and create false positives and false negatives when language expresses the same meaning differently. Code should own execution and hard safety boundaries while semantic models supply bounded judgment.
- **Refs:** PROJECT.md, AGENTS.md, CLAUDE.md

## D-2026-09-23-06 — Import arbitrary job URLs before application processing
- **Area:** product
- **Status:** accepted
- **Decision:** Add a non-sending `job-agent import-url URL` command and matching API. It verifies the supplied page, employer identity, exact role and live status through the existing structured career-search evidence pipeline, then creates or reuses the durable firm, job and contact records and returns the canonical Job Agent candidate. Direct operator imports use the interactive OpenClaw lane, one bounded import attempt, and raw supplied-page judgments before any bounded source fetches; they are not rejected merely for falling outside automated-search preferences. The RPC acknowledgement window is independently configurable so gateway load does not create duplicate abandoned runs. Required employer, role and active-status evidence remains exact; optional date or geography claims whose excerpts fail exact validation are stored as unknown instead of rejecting the verified role. Contradictory descriptive PI flags fail closed: an employer classified as non-legal cannot remain marked as a direct PI employer. A retry may reuse a prior model decision only after refetching every candidate page and passing the current exact-evidence validator. Classification, preparation and sending remain separate commands.
- **Why:** External agents could coordinate stored Job Agent records but could not start from a newly supplied job URL. Durable storage is necessary for deduplication, revisions and auditability, but prior storage should not be a user-facing prerequisite.
- **Refs:** app/services/daily_career_search.py, app/services/job_agent.py, app/api/job_agent.py, app/job_agent_cli.py

## D-2026-09-23-07 — Enrich incomplete job-board identity and audit every URL import
- **Area:** product
- **Status:** accepted
- **Decision:** Keep direct URL extraction raw when the supplied page contains complete employer identity. When a specific public job page proves the role and employer but cannot establish the employer's official domain, run one bounded tool-enabled research pass for that same employer, then freshly fetch and validate every returned source before storage. ## D-2026-09-23-08 — Treat the native agent RPC response as run-bounded on this gateway
- **Area:** infra
- **Status:** accepted
- **Decision:** Give the native OpenClaw `agent` request the full per-call run budget and accept either an immediate `accepted` acknowledgement or a terminal `ok` response. On any timeout, error or cancellation after dispatch, issue a targeted abort and delete the isolated session. Keep the lane semaphore and the outer workflow deadline as the concurrency and total-time boundaries.
- **Why:** The installed gateway documentation promises an immediate acknowledgement, but live logs showed an `agent` response returning only after 643 seconds. The former 90-second acknowledgement window abandoned a still-running Possible OS session, accumulated gateway workers and prevented a valid Skydropx import from reaching verification.
- **Refs:** app/services/llm_gateway.py, OPENCLAW_RPC_ACCEPT_TIMEOUT_S

## D-2026-09-23-09 — Retry terminal OpenClaw history reads without discarding evidence
- **Area:** infra
- **Status:** accepted
- **Decision:** After an OpenClaw run reports terminal success, give `chat.history` a 60-to-120-second read-only budget and retry one timeout. ## D-2026-09-23-10 — Prefer lightweight tool RPC and retain a bounded native-search fallback
- **Area:** infra
- **Status:** accepted
- **Decision:** Official-domain discovery for a supplied job URL first invokes OpenClaw's `web_search` tool directly over native RPC, without starting an agent session. If the gateway has no generic search provider, record that exact failure and run one bounded interactive agent turn using the model provider's native web search. Search results are discovery hints only; the importer must freshly fetch and validate the selected official employer page before storing the job.
- **Why:** Direct tool invocation is materially cheaper under gateway load, but the live OpenClaw installation currently exposes provider-native search only inside agent runs. An optional external search plugin was not installed. The fallback keeps URL import functional without weakening identity or evidence checks.
- **Refs:** app/services/daily_career_search.py, app/services/llm_gateway.py, app/skills/daily-pi-career-search/SKILL.md

## D-2026-09-23-11 — Recover blocked official pages through same-origin content APIs
- **Area:** product
- **Status:** accepted
- **Decision:** When an operator-supplied URL import identifies an official employer page but that page blocks the verification client, try a mechanically derived, public, same-origin WordPress REST representation of that exact page. Replace the candidate evidence URL only after an HTTP 200 response and matching canonical domain. The normal structured employer verifier and exact quoted-evidence checks remain mandatory.
- **Why:** Skydropx's public About page is indexed and browsable but returns HTTP 403 to the bounded verification client, while its official same-origin WordPress endpoint returns the same page content. Rejecting the employer solely because of transport behavior is a false negative; accepting search snippets would weaken evidence integrity.
- **Refs:** app/services/daily_career_search.py, tests/test_daily_career_search.py

## D-2026-09-23-13 — Give external agents one state-aware Job Agent CLI runbook
- **Area:** product
- **Status:** accepted
- **Decision:** Add a dedicated `possibleos-job-application` skill for external agents. It requires the canonical import or Leads-resolution path, per-job classification, draft-only preparation, packet inspection, one explicitly authorized Zoho send, read-only Sent reconciliation, and Communications sync. Revision-bound mutations always use the latest `processing_revision` from `show`; candidate review revisions are not interchangeable. - **Why:** The CLI already exposes the workflow, but an external agent previously assumed jobs had to pre-exist, treated an import stop as the end of the workflow, and could confuse stale queue revisions with application revisions. A discoverable runbook makes the durable state machine and its safety boundaries executable without weakening verification.
