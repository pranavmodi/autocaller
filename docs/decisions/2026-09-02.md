# Decisions — 2026-09-02

## D-2026-09-02-01 — Derive consolidated Lead Finder catalog from publish events
- **Area:** data-arch
- **Status:** accepted
- **Decision:** Build the cross-run lead catalog from completed lead_finder.add_researched_lead tool calls and preserve run/step provenance; do not aggregate mutable run context.
- **Why:** Explicit publish events are canonical, exclude malformed model-authored context by construction, and provide durable provenance for each displayed lead.
- **Refs:** app/services/lead_finder.py; GET /api/lead-finder/results

## D-2026-09-02-02 — Promote researched leads out of the debug workspace
- **Area:** product
- **Status:** accepted
- **Decision:** Make /research-leads a first-class global-navigation workspace and keep /lead-finder focused on agent runs and run-local debugging.
- **Why:** The consolidated lead catalog is an operating surface for reviewing and acting on research, while run traces and controls serve a separate debugging job.
- **Refs:** frontend/app/research-leads/page.tsx; frontend/components/Nav.tsx

## D-2026-09-02-03 — Pause Lead Finder on transient gateway pressure
- **Area:** infra
- **Status:** accepted
- **Decision:** Treat provider timeouts, rate limits, temporary gateway errors, and connection-capacity failures as durable Lead Finder pauses; preserve the failed attempt and context, stop auto-chaining, and require an explicit later step or auto-run start rather than terminating or immediately retrying.
- **Why:** OpenClaw's shared lane can be temporarily saturated for minutes. Immediate retries consume the safety budget and add load, while terminal failure discards a resumable agent trajectory.
- **Refs:** app/services/lead_finder.py; POST /api/lead-finder/runs/{run_id}/resume
