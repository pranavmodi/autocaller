# Decisions — 2026-06-26

## D-2026-06-26-01 — Human-session JS beacon on tracked landing pages (true human signal vs scanner-inflated clicks)
- **Area:** data-arch
- **Status:** accepted
- **Decision:** Tracked email links (`/a/ /c/ /s/`) record a server-side redirect click, but those are dominated by email-security scanners (Proofpoint, Microsoft Safe Links, Mimecast, Barracuda) that fetch URLs without running page JS. To get a trustworthy human signal we add a `session_ready` JS beacon on the destination landing pages (same idea as the AIAudit `session_ready` beacon). possibleos exposes `POST /api/lead-gen/page-event` (public, auth-exempt) recording a `page_session` observation attributed via the `/c/`/`/s/` link code (`lc`, now appended to the consult redirect too). The marketing-site beacon (`<ClickBeacon>`) was delegated to Codex and added to `/consult` + the four `/solutions/*` pages; the standing rule to add it to every tracked landing page is recorded in `getpossibleminds/CLAUDE.md`. A beacon is a near-definitive human-confirmation signal (not 100% — a rare headless-Chrome crawler runs JS — but it eliminates essentially all email scanners); it does NOT clean the click table, it is a parallel trustworthy count.
- **Why:** Day-one analytics showed 61 raw clicks but ~0 confirmed humans (paired same-second multi-link clicks per contact = scanners). Raw redirect clicks cannot distinguish human from scanner; only a JS beacon can.
