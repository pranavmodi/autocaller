## D-2026-07-07-02 — Waves methodology persisted; wave-data gaps identified
- **Area:** process
- **Decision:** The outbound learning loop is formalized as **waves** (one wave
  = one experiment = one curated batch = one experiment_json card) in
  lexvisibility/docs/WAVES_METHODOLOGY.md, linked from a new
  lexvisibility/CLAUDE.md. Ritual: predict before send, change one thing per
  wave, read the /admin compare view after.
- **Gaps to instrument (in priority order):** (1) deliverability layer
  (bounce join + inbox placement) — the funnel currently starts at click,
  missing where wave 1 actually failed; (2) email-open pixel as a distinct
  stage (split open-rate from click-through); (3) per-recipient A/B variant in
  the data, not just the send script; (4) firm/recipient covariates (warmth,
  persona, is-DM, visibility story-type); (5) reply/meeting outcomes joined
  from inbound_emails; (6) send timing + time-to-open; (7) negative signals
  (bounces/unsubs/complaints); (8) report version seen.
- **Why:** Without the deliverability + open + reply layers and the covariates,
  wave results can't distinguish "bad artifact" from "never delivered" or learn
  who/what works — exactly the ambiguity that made wave 1 unreadable.
