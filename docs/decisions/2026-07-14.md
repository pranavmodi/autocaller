# Decisions — 2026-07-14

## D-2026-07-14-01 — Wave-rollup human-session metric now requires interaction evidence, matching the click classifier
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** experiment_rollup no longer counts every session_ready page_session beacon as a human_page_session. classify_page_sessions() groups page_session observations by session_id and labels a session human only with interaction evidence: page_leave dwell >10s (HUMAN_SESSION_MIN_TIME_ON_PAGE_MS), an on-page click event in the same session, or first activity >15min after the item's email_sent observation (HUMAN_SESSION_MIN_DELAY_AFTER_SEND). Scanner-UA sessions -> scanner. Rollup now emits raw_page_sessions alongside human/suspect/scanner_page_sessions; signal_quality per-observation dwell threshold raised 3s->10s to match.
- **Why:** The 2026-07-13 workshop wave (batches 1347c55f… and b549bcbd…) showed email-security scanners now execute JS, emitting session_ready beacons with ~4s dwell, zero clicks, Linux/X11 UAs, arriving within ~2min of send — the rollup reported 34 'human' sessions on 33 sends. The click classifier already caps such clicks at 'suspect'; the session metric applied no such filter. Post-fix the two batches drop to human_page_sessions=2 and =1 (raw 22 and 14), consistent with the 0 human clicks the click classifier already reported.
- **Refs:** app/services/lead_gen_experiments.py, app/cli.py wave-rollup, tests/test_lead_gen_experiments.py

## D-2026-07-14-02 — Landing-page human detection moves to a progressive-gesture funnel (tap-to-reveal); dwell alone is no longer trusted
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** The ClickBeacon on tracked landing pages (getpossibleminds components/analytics/click-beacon.tsx) now emits progressive-funnel steps in addition to session_ready: first_pointer (first real pointer/scroll/touch/key gesture), scroll_50 (>=50% scroll depth), and content_revealed (dispatched by a new RevealPanel tap-to-reveal gate, components/analytics/reveal-panel.tsx). The workshop 'instruction one' gift is now behind RevealPanel. classify_page_sessions() tracks these per session and returns {quality, reached_reveal, has_gesture}; wave-rollup adds gesture_page_sessions and revealed_page_sessions, which are the metrics to trust over human_page_sessions.
- **Why:** 2026-07-13 workshop analysis showed modern email-security scanners execute page JS AND emulate dwell (held pages ~15-25s, rotated spoofed UAs incl. iPhone OS 10_3_1, two recipients hit with identical 16.9s dwell one minute apart), defeating the dwell>10s heuristic — 40 'human' sessions on batch A were almost entirely bots, 0 registrations. A gesture a scanner does not perform (pointer move, scroll, tap-to-reveal) is the reliable pre-conversion human signal; the tap-to-reveal deliberately manufactures one. Dwell/late-arrival kept only as weak fallbacks in human_page_sessions.
- **Refs:** getpossibleminds: click-beacon.tsx, reveal-panel.tsx, workshops/ai-for-filevine-case-managers/page.tsx; possibleos: app/services/lead_gen_experiments.py, app/cli.py wave-rollup, tests/test_lead_gen_experiments.py
