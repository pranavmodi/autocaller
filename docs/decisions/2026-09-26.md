# Decisions — 2026-09-26

## D-2026-09-26-01 — Explicit local cancellation with contextual reason suggestions

- **Area:** product
- **Status:** accepted
- **Decision:** Add revision-bound quit for stopped pre-submit browser applications, plus model-generated editable reason suggestions from job/question context. Preserve history and answers, never promote a quit reason to profile facts, and keep submission uncertainty locks. Best-effort browser cleanup cannot prevent cancellation.
- **Why:** Users need to decline a role when a question reveals a relocation or other preference mismatch, without supplying a false form answer or resuming the agent. Local cancellation does not imply employer-side withdrawal.
- **Refs:** `app/services/job_browser.py`, `app/skills/job-quit-reasons/SKILL.md`, `frontend/components/JobBrowserApplication.tsx`

### D-2026-09-26-02 — Saved targeted searches and immutable run findings
- Area: product
- Status: accepted
- Decision: Separate revisioned search configurations from canonical jobs. Reuse
  career_search_runs as a durable queue with immutable settings snapshots and per-job
  outcomes. Preserve existing schedule in the default search; timer enqueues due
  saved searches and one backend worker drains them. One scheduled attempt per local
  day; retries remain explicit. Report rediscoveries without duplicate applications.
- Why: Users need precise independent targeting, observable results from every run,
  and reliable requirement/preference distinctions without losing prior evidence.
- Evidence: app/services/job_saved_searches.py; frontend/components/JobSearches.tsx;
  tests/test_job_saved_searches.py. Prompt version v1.80; call template unchanged.
