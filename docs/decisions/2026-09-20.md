# Decisions — 2026-09-20

## D-2026-09-20-01 — Start Job Agent search as an operator action
- **Area:** product
- **Status:** accepted
- **Decision:** Job Agent external search uses saved role, industry and location preferences, verifies legal-domain employers and live job/geography evidence, deduplicates mechanically, and imports into the review queue without classification or application authority. Manual runs remain distinct from the scheduled PI search.
- **Why:** This delivers observable search and shortlisting first while preventing a search request from consuming a daily slot or implicitly authorizing classification, email, or form submission.
- **Refs:** `app/services/daily_career_search.py`, `app/services/job_agent.py`, `frontend/app/job-agent/page.tsx`

## D-2026-09-20-02 — Preserve job discovery provenance
- **Area:** data architecture
- **Status:** accepted
- **Decision:** Every Job Agent posting exposes a normalized `job_source`: `external_search` for jobs produced by the evidence-backed career search and `possibleos` for listings collected from the wider Possible OS firm directory. The queue, API and CLI can filter by this field. Legacy rows derive it from their stored discovery provider until the normal sync persists it.
- **Why:** Operators need to distinguish jobs found by the targeted search from listings already present in Possible OS without relying on titles, URLs or timestamps.
- **Refs:** `app/services/job_agent.py`, `app/api/job_agent.py`, `frontend/app/job-agent/page.tsx`

## D-2026-09-20-03 — Reconcile interrupted manual searches at startup
- **Area:** reliability
- **Status:** accepted
- **Decision:** On backend startup, acquire the career-search advisory lock non-blockingly. When acquired, mark any durable manual-search run still labeled `running` as `interrupted`, record the restart reason, and require an explicit operator retry. Scheduled runs are left to their existing runner and stale-run handling.
- **Why:** Manual search executes in an in-memory task while progress is durable. A process restart can end the worker without updating the final status, which otherwise leaves the UI permanently stuck and prevents another search.
- **Refs:** `app/services/daily_career_search.py`, `app/main.py`, `frontend/app/job-agent/page.tsx`

## D-2026-09-20-04 — Make manual-search employer eligibility configurable
- **Area:** product
- **Status:** accepted; supersedes the legal-domain-only eligibility portion of D-2026-09-20-01
- **Decision:** A manual Job Agent search derives allowed employer industries and industry-specific queries from the saved, delimiter-separated `preferred_industries`. An active result must prove a configured preferred-industry match from an official employer page; legal-domain identity is descriptive and does not bypass the settings. The scheduled PI search retains its direct-PI-employer requirement.
- **Why:** Search settings must control which employer industries can pass verification, so medical imaging, health insurance and future industries do not require another hard-coded verifier change.
- **Refs:** `app/services/daily_career_search.py`, `app/skills/daily-pi-career-search/SKILL.md`, `frontend/app/job-agent/page.tsx`

## D-2026-09-20-05 — Share verified application contacts at firm scope
- **Area:** data architecture
- **Status:** accepted
- **Decision:** Manual search may discover official employer contact pages and persist only source-verified employer-domain recruiting or routing emails in `firm_contacts`. Job rows expose the best eligible shared firm contact and support `contact_desc` ordering; contacts are not copied into each job posting.
- **Why:** Multiple roles from one employer should reuse one auditable contact record, while unsuitable, guessed and third-party addresses remain excluded from application routing.
- **Refs:** `app/services/daily_career_search.py`, `app/services/job_agent_processing.py`, `app/services/job_agent.py`, `frontend/app/job-agent/page.tsx`
