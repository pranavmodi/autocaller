# Decisions — 2026-09-17

## D-2026-09-17-01 — Uncapped, resumable Job agent collection
- **Area:** data-arch
- **Status:** accepted
- **Decision:** Replace the total import limit with durable source snapshots and transactional batch checkpoints. Automatically sync local source changes every minute, preserve explicit filters, pause between batches, retain reviews and surface progress/errors. Paginate all workspace audit history. Default queue sorting to newest actual posting date with unknown dates last.
- **Why:** The user wants every discovered matching job reachable without starvation from a newest-100 import cap. Fixed database snapshots prevent concurrent source updates from shifting pages; bounded transactions provide operational control without truncating the work set.
- **Refs:** `docs/JOB_AGENT.md`, `app/services/job_agent.py`, `tests/test_job_agent.py`

## D-2026-09-17-03 — Category resumes and explicit Zoho application processing
- **Area:** product
- **Status:** accepted
- **Decision:** Classify job responsibilities using structured LLM output into user-editable categories, each mapped to a reusable one-page PDF. Automatically classify stored/new jobs; ambiguous or unmapped jobs need review. ## D-2026-09-17-04 — Classify jobs only on operator request
- **Area:** product
- **Status:** accepted; supersedes the automatic-classification clause of D-2026-09-17-03
- **Decision:** Keep bulk classification disabled by default. Classify only the specific job for which the operator requests classification; leave all other queued jobs pending. Retain the Settings flag for an explicit future opt-in to bulk processing.
- **Why:** The operator only needs resume selection when considering a manual application, so classifying every discovered listing wastes model work and obscures the review queue.
- **Refs:** `docs/JOB_AGENT.md`, `app/services/job_agent_processing.py`, `frontend/components/JobApplicationControls.tsx`

## D-2026-09-17-07 — Isolate on-demand classification from the main OpenClaw queue
- **Area:** reliability
- **Status:** accepted
- **Decision:** Route Job Agent model calls through the isolated `openclaw/neo` agent, gate gateway requests per agent rather than globally, and cap classification calls at 120 seconds. Show queued, active and needs-review states distinctly in the UI.
- **Why:** A single-job Avaness classification spent seven minutes behind unrelated firm-research work in the stateful main-agent lane, leaving a contradictory active/waiting display. A later retry showed that a process-wide gateway semaphore also serialized independent agents. The gateway no longer advertises the historical `openclaw/proxy` alias; its configured lightweight `neo` agent and a per-agent client gate let narrow structured calls proceed without inheriting the main research backlog.
- **Refs:** `app/services/job_agent_processing.py`, `frontend/components/JobApplicationControls.tsx`, `docs/JOB_AGENT.md`

## D-2026-09-17-08 — Corroborate inaccessible job sources without weakening application evidence
- **Area:** reliability
- **Status:** accepted
- **Decision:** Retry and record direct page-fetch failures, then permit the Job Agent to verify the same employer and exact role through a directly fetched employer page or established job platform. Keep exact quoted evidence, trusted-host checks, company identity validation and the original role URL in the application. Block before composition when neither the imported source nor a corroborating role page can be fetched.
- **Why:** Some live listings block or time out direct fetches even though the same current opening is independently published. Silently discarding those errors produced misleading false negatives and made diagnosis impossible.
- **Refs:** `app/services/job_agent_research.py`, `app/skills/job-application-agent/SKILL.md`, `tests/test_job_agent_processing.py`
