# Decisions — 2026-08-29

## D-2026-08-29-01 — Use one recursive JSON viewer across Lead Finder debug data
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** Reuse the expandable syntax-highlighted JSON tree for every structured Lead Finder debug surface and recursively decode valid object/array JSON found inside string fields for presentation only.
- **Why:** Gateway messages and assistant outputs often contain serialized JSON inside strings; leaving those values escaped makes the real context difficult to inspect, while changing the persisted representation would compromise raw fidelity.
- **Refs:** `frontend/app/lead-finder/page.tsx`

## D-2026-08-29-02 — Persist bounded Lead Finder auto-run state on the run
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** Unattended Lead Finder execution chains the existing durable one-transition steps from server-persisted run state, with operator stop and a bounded additional-step budget, rather than relying on a browser loop.
- **Why:** The run must continue and recover without an open browser while preserving the same inspectable reasoning/tool boundary and preventing manual and automatic next-step races.
- **Refs:** `app/services/lead_finder.py`, `lead_finder_runs.auto_run_*`
