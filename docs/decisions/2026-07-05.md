# Decisions — 2026-07-05 (UTC)

## D-2026-07-05-01 — Firm mirror repointed from v1 pif-info to the v2 firm-intel contract
- **Area:** data-arch
- **Decision:** `pif_directory_firms` now syncs from EmailTag's v2 firm-intel
  API (`/api/v2/firm-intel/firms` delta feed, `X-PIFStats-Auth-Token` header
  auth) via the new `app/services/firm_intel_sync.py`; the v1
  `sync_pif_directory` is deprecated in place. Local additions: `firm_intel_aliases`
  (local alias resolution), `firm_intel_sync_state` (watermark), new PifFirmRow
  columns (`canonical_website`, `metro`, `warm_score`, `vendor_stack`,
  `profile_source`). Full v2 profile retained in `raw_json`.
- **Why:** The 2026-07-05 emailtag merge deploy made all v1 routes cookie-auth
  only — the daily header-token mirror sync had been silently 401ing. The v2
  contract is the designed replacement (MIGRATION_PLAN P1) and carries warmth,
  vendors, and aliases the v1 payload lacked.
- **Refs:** app/services/firm_intel_sync.py, app/db/models.py (FirmAliasRow,
  FirmIntelSyncStateRow), docs/product/tasks/PACKET_PIF_MIRROR_V2.md

## D-2026-07-05-02 — Sync client hardened: 25-item pages + 5xx retry, not server-side fixes
- **Area:** data-arch
- **Decision:** The v2 delta feed builds full profiles per item (~11s at
  limit=100) and 502s under load; the client now defaults to
  `FIRM_INTEL_PAGE_SIZE=25` and retries 5xx/transport errors 4x with backoff.
  Watermark advances only after a fully successful run, so failed crawls
  re-cover safely.
- **Why:** Client-side resilience ships now; server-side profile-build
  performance is EmailTag work, deferred until the 502 rate under normal load
  proves it necessary.
- **Refs:** app/services/firm_intel_sync.py (_page_size, _get_with_retry)

## D-2026-07-05-03 — LexVisibility integrates via the contract, not new plumbing
- **Area:** product
- **Decision:** EmailTag gained (E5) candidate-firm creation
  (`POST /api/v2/firm-intel/firms`, idempotent by canonical domain → alias →
  exact name) and `report_viewed`/`report_engaged` event types; the v2 profile
  now publishes full research + people detail (bios, publications, offices,
  awards) so the possibleos mirror replicates everything LexVisibility's
  personalization needs. LexVisibility will resolve AI-answer firm mentions
  against the local mirror, create unknowns upstream in EmailTag, and push
  report engagement into the firm event stream.
- **Why:** One identity graph and one event stream across
  emailtag/possibleos/LexVisibility; avoids a parallel firm store and the
  entity-resolution embarrassment class of failures.
- **Refs:** /home/pranav/emailtag commits 1539145 (E1), 31e97fb (E5);
  docs/product/tasks/PACKET_FIRMINTEL_E5_lexvis_contract.md
