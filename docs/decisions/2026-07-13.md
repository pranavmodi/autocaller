# Decisions — 2026-07-13

## D-2026-07-13-01 — Workshop tracked links get their own /w/ kind instead of per-link dest on /s/
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** Added `kind="workshop"` short links (`/w/<code>`, `build_short_workshop_link`, `WORKSHOP_PAGE_URL` dest env) rather than adding a per-link destination column to `audit_links`. The /w/ redirect appends per-recipient prefill params (contact_name/contact_email/firm_name) by resolving the contact server-side.
- **Why:** Matches the existing one-kind-per-destination pattern (audit/consult/solution/intake), needs no migration, and keeps recipient PII out of email URLs (params are added only at redirect time from the DB, so the mailed link stays a bare short code).

## D-2026-07-13-02 — Close CLI-parity gaps exposed by the workshop A/B wave; daily budget now CLI-settable
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** Added `contacts select` (fresh-cohort selection by persona/vendor/per-firm cap), `lead-gen items` (item<->contact map), `lead-gen workshop-links` (mint/reuse /w/ links), `lead-gen schedule-wave` (template compose + approved scheduled sends per item), and `lead-gen transport --daily-budget N` (sets weights_json.daily_send_budget). docs/cli.md §3 rows + §10 A/B-wave recipe; SKILL.md synced.
- **Why:** The 2026-07-13 workshop wave required raw SQL for selection/item lookup and direct service calls for link minting + a bespoke compose/schedule driver — violations of the CLI-parity golden rule. These commands make the same wave reproducible end-to-end from the CLI; the daily send budget was UI/DB-only and is a policy rail operators must be able to move from a terminal.

## D-2026-07-13-03 — Registration alerts go WhatsApp-first (openclaw CLI), not Telnyx SMS
- **Area:** lead-gen
- **Status:** accepted
- **Decision:** product-interest signups alert the operator via `openclaw message send --channel whatsapp` (OPERATOR_WHATSAPP) with Telnyx SMS as fallback (`app/services/operator_sms.py::notify_operator`); workshop registrants get a Resend confirmation email (`send_workshop_registration_confirmation`).
- **Why:** Telnyx SMS to the operator's +91 number fails with 40306 (India DLT/alpha-sender rules) — the same silent failure mode the inline consult SMS alert has. WhatsApp via the openclaw gateway is the channel that actually reaches the operator (proven by the daily-run notifier). Consults/dashboard still carry inline Telnyx copies; migrate them to `notify_operator` when next touched.
