# Decisions — 2026-09-28

## D-2026-09-28-01 — Recover job-board failures onto exact official application pages
- **Area:** product
- **Status:** accepted
- **Decision:** A failed model-audited pre-form navigation triggers a bounded search for the exact role on the employer site or official ATS. The worker verifies employer, role and application evidence, then continues in a fresh browser on that official page.
- **Why:** Aggregator overlays and sign-in walls should not stall an authorized application or be confused with a possible submission, while exact-role verification prevents applying through a generic talent pool or different opening.
- **Refs:** `app/services/job_application_source.py`, `app/services/job_browser.py`

## D-2026-09-28-02 — Use role-specific judgment for subjective application answers
- **Area:** product
- **Status:** accepted
- **Decision:** The website application agent should answer subjective preference and positioning fields using reasonable role-specific judgment, including market-aligned desired compensation, while continuing to ask for unknown legal, identity, credential and other hard facts.
- **Why:** Routine preference questions should not stall an authorized application, but presenting the applicant as viable must remain grounded in verified experience and must never create false biographical or legal claims.
- **Refs:** `app/skills/job-browser-agent/SKILL.md`, `app/skills/possibleos-job-applicant-context/SKILL.md`

## D-2026-09-28-03 — Continue through low-risk application defaults
- **Area:** product
- **Status:** accepted
- **Decision:** The website application agent should infer ordinary low-risk negative defaults, such as no employee referral when none is identified, and continue through noncritical ambiguity. It should stop only for unknowns that are critical to truthful representation or cannot be safely inferred.
- **Why:** Routine binary questions and recoverable form ambiguity should not stall applications, while legal, identity, authorization, credential, background and other consequential facts remain evidence-bound.
- **Refs:** `app/skills/job-browser-agent/SKILL.md`, `app/skills/possibleos-job-applicant-context/SKILL.md`

## D-2026-09-28-04 — Infer conservative experience duration from dated work
- **Area:** product
- **Status:** accepted
- **Decision:** The website application agent should calculate completed years from dated, clearly relevant work and treat parenthetical tool/provider lists as examples unless the form explicitly requires a named product.
- **Why:** A resume need not repeat every product example used to label a supported capability; conservative date-based answers should not stall an authorized application.
- **Refs:** `app/skills/job-browser-agent/SKILL.md`, `app/skills/possibleos-job-applicant-context/SKILL.md`

## D-2026-09-28-05 — Do not clear completed multi-select fields
- **Area:** engineering
- **Status:** accepted
- **Decision:** The browser agent must not use ambiguous `x`, Close, or unlabeled controls to dismiss a multi-select after choosing values. It should keep the choices and proceed to a clearly identified next control.
- **Why:** ATS multi-select widgets often use those controls to remove a chip or clear the field, and their element IDs change after every selection.
- **Refs:** `app/skills/job-browser-agent/SKILL.md`
